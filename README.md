# 期號檢查器

自動核對彩票期號在「換日」與「跨年」時是否正確歸零的檢查工具。單一 HTML 檔案，開啟即用，不需安裝任何環境。

---

## 這個工具在解決什麼

彩種的期號會在每天換日時把流水號歸零，跨年時還要同時更換年份前綴。例如：

```
20260905 1440   ← 前一天最後一期
20260906 0001   ← 換日後第一期，流水號必須歸零
```

一旦歸零失敗（流水號沒重來、或年份沒換），會直接影響開獎與結算。過去這件事靠人工逐一開啟前台頁面目視核對，數十至上百個彩種逐一比對，耗時且容易漏看，跨年當晚壓力尤其集中。

本工具把這個核對過程自動化：抓線上實際期號 → 依格式推算「應該是多少」→ 兩者比對 → 只把對不上的挑出來。

---

## 運作方式

```
① 取得線上資料 ──→ ② 反推期號格式 ──→ ③ 推算應有值 ──→ ④ 比對並分類
   各彩種目前期號         由實際期號長度         當日/當年首期        線上實際 vs 推算值
   + 開獎歷史             判斷屬哪一種家族                            對不上才是異常
```

關鍵設計：**「應有值」是獨立推算出來的，不是從線上資料抄的。** 若兩邊都取自同一來源，就會變成自己跟自己比，永遠 100% 通過，檢查就失去意義。

| 欄位 | 來源 |
|---|---|
| 歸零前最後一期 | 線上開獎歷史 |
| 歸零後第一期 | 線上開獎歷史 |
| 發生時間 | 線上開獎歷史 |
| **應為** | **程式依格式推算** |
| 結果 | 上兩者比對 |

### 支援的期號格式

格式不是預先設定的，而是由線上實際期號的長度與結構反推：

| 家族 | 長度 | 範例 | 說明 |
|---|---|---|---|
| `ymd4` | 12 | `202609060001` | 年月日 + 4 位流水，每日歸零 |
| `ymd3` | 11 | `20260906001` | 年月日 + 3 位流水，每日歸零 |
| `ymd2` | 10 | `2026090601` | 年月日 + 2 位流水，每日歸零 |
| `roc` | 9 | `115000001` | 民國年 + 6 位流水，全年累計 |
| `y3` | 7 | `2026001` | 西元年 + 3 位流水，全年累計 |
| `yy3` | 5 | `26001` | 年後兩碼 + 3 位流水，全年累計 |

不屬於上述任何一種（期號不含年份或日期）者，跨點本來就不會變動，標記為「免驗」不予檢查。

### 判定結果

| 結果 | 意義 |
|---|---|
| **正確** | 歸零後第一期與推算值相符 |
| **錯誤** | 兩者不符，需要處理 |
| **★跨年** | 該次歸零同時跨越年度（附加標記） |
| **年份正確** | 全年累計型彩種，非 1/1 不會歸零，僅能確認年份前綴無誤 |
| **待驗** | 開獎歷史回溯不到換日交界，尚無法判定 |
| **尚未發生** | 指定的日期還沒到 |
| **免驗** | 期號不含年份／日期，跨點不會變動 |

## 這個工具刻意處理的三種例外

這些是實務上真正會誤判的情況，也是本工具與「單純比對字串」的差別所在。

### 1. 資料斷層不當成歸零

開獎歷史底部偶爾會殘留一筆很久以前的孤兒紀錄。若只看「年份有沒有變」，會把這種跳點誤認為跨年而誤報。

工具會計算歷史紀錄的正常開獎間隔，當交界處的間隔超過正常值的 5 倍時，視為資料斷層並略過該跳點。

**原則：寧可回報「無法判定」，也不要誤報「錯誤」。** 誤報會讓人白跑一趟並失去對工具的信任。

### 2. 停開時段不是斷層

部分彩種每天有固定停開時段（例如夜間收盤到隔日開盤中間空數小時），跨日交界處本來就會有很長的間隔。若一律套用斷層規則，反而會把最需要驗證的那一檔擋掉。

因此當交界後第一期**已經等於應有值**時，不論中間空多久都判定為正確，並在說明欄註記屬停開時段。

### 3. 地區封鎖不能當成通過

當來源 IP 被平台阻擋時，HTTP 仍會回傳 200、JSON 結構也合法，只是內容為錯誤碼。若未辨識這種回應，會產出一張「0 筆異常、全部通過」的報表 —— 這比直接報錯危險得多。

工具偵測到此類回應時會**直接中止並提示，不產出任何報表**。

## 使用方式

### 安裝

不需安裝。

1. 右上角 **Code → Download ZIP**，解壓縮
2. 用瀏覽器開啟 `index.html`

> ⚠️ 請務必**先下載到本機再開啟**。GitHub 與雲端硬碟的檔案預覽畫面不會執行 JavaScript，直接在預覽頁點按鈕不會有反應。

### 首次設定

本檔案**不含任何平台網址**，第一次開啟時要設定一次，之後就不用再做了。

表格一個平台一列，填三個欄位（不夠可按「＋ 新增一列」）：

| 欄位 | 說明 | 範例 |
|---|---|---|
| 代號 | 2～3 個英文字母，自己好認就好 | `AA` |
| 平台名稱 | 顯示用的名稱 | `平台一` |
| 網址 | 完整網址，含 `https://`，結尾不加斜線 | `https://xxx.example.com` |

填好按「完成，開始使用」即可。網址少了 `https://` 或漏填代號都會擋下並提示。

設定只儲存在你這台電腦的 `localStorage`，不會上傳、也不會寫回檔案。因此本檔案可以公開存放而不洩漏內部資訊。

> 內部使用者請向主管或部門共享資料夾索取平台清單。

### 日常操作

1. 勾選要檢查的平台
2. 選擇檢驗模式
   - **最近一次換日** —— 日常每日檢查
   - **指定日期** —— 選 1/1 即為跨年檢查
3. 按 **直接連線取數**
4. 點「只看要處理的（錯誤）」，處理標示為錯誤的項目

### 關於「待驗」

「待驗」不代表有問題，而是**現在還驗不到** —— 該彩種的換日交界已被推出可查詢的歷史範圍。

每檔彩種必須在**它自己換日之後的 2 小時內**重跑才驗得到。工具會自動依各彩種的換日時刻，算出建議的重跑時間窗並顯示在結果上方。

需要補驗時請按 **「只重驗還沒結論的」**。已有結論的彩種不會被重新查詢，也不會被覆蓋 —— 否則稍後重跑時，先前已驗得的交界早已超出歷史範圍，原本的「正確」會倒退成「待驗」，等於把結果洗掉。

## 功能

- 平台分頁，各分頁標示該平台的檔數與錯誤數
- 分類統計卡片，可點擊即時篩選
- 彩種名稱／期號／說明全文搜尋
- 依類別篩選（每日歸零／全年累計／不隨日期）
- 依平台分組檢視、欄位排序
- 匯出目前篩選結果為 CSV
- 同一檢驗日結果累積保存，支援分次補驗

## 技術說明

| 項目 | 內容 |
|---|---|
| 結構 | 單一 HTML 檔案，含全部 HTML／CSS／JavaScript |
| 相依套件 | 無。零第三方套件、無 CDN、無框架 |
| 後端 | 無。純前端執行 |
| 資料儲存 | 瀏覽器 `localStorage` |
| 資料流向 | 全部在本機瀏覽器完成，不經任何第三方伺服器 |
| 對外連線 | 僅連線至使用者自行設定的平台網址 |
| 操作性質 | 唯讀查詢，不包含任何寫入或交易操作 |

### 判定一致性驗證

判定核心移植自部門既有的 Node 版工具，為確保移植過程中規則沒有走樣，以相同輸入同時餵入兩個版本逐案比對：

- **65 案**逐案比對輸出完全一致（六種格式家族、資料斷層、停開時段、跨年、年份未換、流水未歸零等情境）
- **24 案**交叉驗證通過（六種格式 × 正常／年份未換／流水未歸零）

## 已知限制

| 限制 | 說明 |
|---|---|
| 需連線至內部網路環境 | 來源 IP 受限時無法取數，工具會中止並提示 |
| 歷史筆數上限 | 平台僅回傳固定筆數的開獎歷史，高頻彩種涵蓋時間短，需在換日後 2 小時內執行 |
| 結果不跨裝置 | 記錄存於各自瀏覽器，交接時需匯出 CSV |
| 相依前台介面結構 | 平台改版調整欄位時需同步修正 |
| 無稽核軌跡 | 不記錄執行者與執行時間 |
